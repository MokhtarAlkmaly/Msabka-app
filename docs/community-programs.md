# أقسام المركز وبرامج المجتمع

## الواجهة والسجلات

- تبويبات أفقية أعلى الصفحات المحمية: القرآن الكريم، التدريب والتأهيل (`/training`)، المساعدات والرعاية وكفالة الأيتام (`/care`). تعمل بروابط مستقلة ومع الرجوع والتقدم والتحديث، وتُمرّر أفقيًا على الهاتف.
- سجل المجتمع مستقل عن جدول طلاب القرآن. لا يشترط أن يكون المستفيد طالب قرآن.
- التدريب: التعليم المبكر (روضة وتمهيدي)، المهني والحرفي (خياطة وتطريز ونقش وتصميم)، والصحي والمجتمعي (إسعافات أولية).
- الرعاية: توزيع السلال، توزيع المبالغ، الرعاية التعليمية للأيتام، والكفالة الاقتصادية للأيتام.
- إضافة وتعديل وحذف السجلات مع تأكيد الحذف، والبحث بالاسم والهاتف وولي الأمر والمجموعة والكافل، والتصفية حسب البرنامج والحالة. رابط كل برنامج في البطاقات يفتح سجلاته في الصفحة نفسها.
- كل صف يمثل **مشاركة أو خدمة واحدة** وليس شخصًا فريدًا. يجوز تكرار اسم الشخص في برامج أو تواريخ مختلفة. العدادات تعد السجلات، ولا تدّعي إحصاء الأشخاص الفريدين.

## حقول السجل

البرنامج، اسم المستفيد/رب الأسرة، نوع المستفيد، ولي الأمر/الوصي، الهاتف، المنطقة، تاريخ التسجيل أو الخدمة، الحالة، والملاحظات.

حقول متكيّفة مع البرنامج:

- الروضة والتمهيدي: نوع المستفيد طفل واسم ولي الأمر إلزامي.
- التدريب: اسم الدورة/المجموعة (مثل الدفعة الأولى)، وحالات مسجّل، قيد التدريب، أتم البرنامج، ملغي.
- السلال الغذائية: عدد سلال صحيح موجب، من 1 إلى 100000.
- المساعدات المالية والكفالة الاقتصادية: مبلغ موجب حتى منزلتين عشريتين، وعملة محددة (ريال يمني أو سعودي أو دولار). العملات لا تُجمع معًا ولا تُحوّل.
- رعاية الأيتام التعليمية والاقتصادية: نوع المستفيد يتيم واسم الوصي إلزامي، واسم الكافل/الجهة الداعمة اختياري.
- حالات الرعاية: مسجّل/بانتظار الخدمة، قيد التنفيذ/رعاية مستمرة، تم تقديم الخدمة، ملغي.
- ملخص الرعاية يحتسب فقط الحالة «تم تقديم الخدمة» ضمن نتائج البحث والفلاتر الحالية. يفصل مبالغ كل عملة، ويعد السلال التي وُزّعت فقط. قيمة المبلغ في سجل قيد المتابعة ليست مصروفًا منفذًا.

لتوثيق خدمة جديدة أو دفعة كفالة لاحقة، أضف سجلًا جديدًا بتاريخها. لا تُنشأ دفعات أو استحقاقات دورية تلقائيًا. اسم الكافل والمجموعة نصان، وليسا سجل كفلاء أو دورات مستقلاً بعد. الحضور والشهادات وإدارة الدورات ككيانات منفصلة ليست ضمن هذه المرحلة.

## تفعيل قاعدة البيانات (مطلوب قبل استخدام السجلات)

على قاعدة المشروع الحالية، طبّق مرة واحدة:

`supabase/migrations/20261015100000_community_records.sql`

يُنفّذ عبر مسار نشر الترحيلات المعتاد أو SQL Editor في لوحة Supabase، بعد الترحيلات السابقة التي توفر `can_read_user_data` و`update_updated_at_column`.

**لم يُطبّق هذا الترحيل على القاعدة السحابية من بيئة التطوير.** دون الترحيل تعرض الواجهة رسالة تحديث قاعدة البيانات بدل إظهار سجل فارغ أو نجاح وهمي. بعد تطبيقه، اضغط «إعادة المحاولة» أو «تحديث».

حدّثنا `supabase/full-schema.sql` أيضًا للإنشاء من الصفر. لا تحتاج تشغيل الملف الموحد على قاعدة مهيأة؛ يكفي الترحيل الجديد.

الجدول `community_records` يفرض قيود البرنامج/القسم، الحالات، أسماء المستفيدين، مبالغ وعملات البرامج النقدية، كميات السلال وبيانات الأطفال والأيتام. تُحذف السجلات تلقائيًا عند حذف حساب المالك من `auth.users`. أُضيف الجدول كذلك إلى عملية حذف قاعدة بيانات الحساب الحالية.

## الحفظ والصلاحيات

- **الحفظ سحابي مباشر ويتطلب الإنترنت**. لا تستخدم هذه السجلات SQLite ولا طابور المزامنة القديم. لا تُخزّن سجلات المجتمع في localStorage أو IndexedDB. النسخ الاحتياطية القديمة لسجلات القرآن لا تتضمن هذا الجدول.
- لا يُعلن نجاح الحفظ أو الحذف إلا بعد استجابة قاعدة البيانات؛ خطأ الحفظ يبقي النموذج والبيانات المدخلة لإعادة المحاولة.
- جميع عمليات القراءة مقيدة بالمالك والقسم، وتحمّل النتائج على دفعات لتجاوز حد الاستجابة الافتراضي في Supabase.
- RLS يسمح بالقراءة حسب `can_read_user_data`: المالك، والمسؤول، ومن مُنح إذن الاطلاع وفق نظام المشروع الحالي. الكتابة والحذف للمالك فقط، مع منع نقل ملكية السجل.
- وضع الاطلاع يعطّل أدوات الكتابة، وتتحقق طبقة التخزين منه مرة أخرى. عند تبديل الحساب أو القسم تُغلق النماذج ويُعاد تحميل سجلات السياق الجديد؛ لا توجد بيانات تجريبية ضمن سجلات المستخدم.

## الاختبارات

```sh
npm run test:community
npm run test:sql
npx tsc --noEmit
npm run build:dev
```

اختبارات المجتمع تغطي توزيع البرامج الأحد عشر، التحقق من الحقول، البحث والتصفية، فصل العملات واستبعاد غير المكتمل من الملخص، صفحات التحميل، عمليات التخزين، انقطاع الاتصال، تبديل الحساب، ومنع الكتابة أثناء الاطلاع. اختبارات PostgreSQL عبر PGlite تغطي الترحيل الفعلي وقيوده وسياسات القراءة والكتابة وسحب إذن الاطلاع وإنشاء القاعدة الموحدة.

للفحص اليدوي بعد تطبيق الترحيل: أضف طفلًا مع ولي أمر، ومتدربًا في الخياطة، وتوزيع سلال، ومساعدة نقدية، وكفالة اقتصادية؛ عدّل الحالات ثم حدّث الصفحة للتحقق من الحفظ. جرّب حسابًا آخر بلا إذن ثم بإذن قراءة. تحقّق من فصل العملات ومن عدم احتساب السجلات الملغاة أو قيد المتابعة ضمن الخدمات المكتملة.
